and peers reach this head in plaintext. Something else must protect this

Collectors and peers reach the head over mutual TLS. Each collector verifies
the head as `head.tallyowl.internal` against the authorities in
`deployment.tls.authorities`, and enrolls with a role token. See
docs/DEPLOYMENT.md section 7c for how to make one.

{{- if .Values.deployment.maintenance.enabled }}

A MAINTENANCE JOB IS ENABLED, SO THE HEAD IS STOPPED.
Read the result, then turn the Job off to start the head again:
  kubectl --namespace {{ .Release.Namespace }} logs --selector tallyowl.io/component=maintenance
  helm upgrade {{ .Release.Name }} <chart> --namespace {{ .Release.Namespace }} \
    --reuse-values --set deployment.maintenance.enabled=false
{{- else }}

To make a key for an application, or a session for an operator:
  `kubectl exec` cannot do this. Each verb that changes the store needs the
  data directory to itself, and the running head holds it. Run the verb as a
  maintenance Job. The head stops while the Job is enabled.

  helm upgrade {{ .Release.Name }} <chart> --namespace {{ .Release.Namespace }} \
    --reuse-values \
    --set deployment.maintenance.enabled=true \
    --set 'deployment.maintenance.args={provision,<project>}'
  kubectl --namespace {{ .Release.Namespace }} wait --for=condition=complete --timeout=5m \
    job --selector tallyowl.io/component=maintenance
  kubectl --namespace {{ .Release.Namespace }} logs --selector tallyowl.io/component=maintenance
  helm upgrade {{ .Release.Name }} <chart> --namespace {{ .Release.Namespace }} \
    --reuse-values --set deployment.maintenance.enabled=false

The key is printed once, in the Job log. Store it as a Secret immediately. The
last command deletes the Job. Give the collector release the name of the
Secret in `deployment.apiKeySecret.name`, never the value.
See docs/DEPLOYMENT.md section 9.
{{- end }}
